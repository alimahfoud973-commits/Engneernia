# دليل النشر

> يفترض هذا الدليل خادماً واحداً يشغّل Node، وPostgreSQL 16، وتخزيناً متوافقاً
> مع S3. كل قيمة هنا تأتي من الإعداد، ولا يوجد نطاق ولا مفتاح مكتوب في الكود.

---

## ١. ما يحتاجه التشغيل

| المكوّن | الحد الأدنى | لماذا |
|---|---|---|
| Node | ٢٢ | مثبت في `engines` |
| PostgreSQL | ١٦ | `gen_random_uuid()`، `make_interval(secs =>)`، وسياسات RLS كما كُتبت |
| تخزين S3 | أي متوافق | **الملفات على القرص مرفوضة في الإنتاج** — الخادم يرفض الإقلاع |
| HTTPS | إلزامي | كعكة الجلسة `Secure` و`__Host-`؛ بلا HTTPS لا تُحفظ الجلسة أصلاً |

**بشأن سوريا:** لا شيء هنا يفترض مزوّداً بعينه ولا بوابة دفع دولية. المدفوعات
يدوية بإيصال يراجعه المالك (قرار المالك §١٠)، والتخزين أي خدمة متوافقة مع S3.

## ١-ب. استضافة مجانية للبداية — ما يعمل وما لا يعمل

**يعمل:** المنصة تُقلع وتعمل بكامل نموذج حمايتها على أي PostgreSQL مُدار مجاني
يمنحك حساباً بصلاحية `CREATEROLE`. مُثبت بالقياس — التفصيل والوصفة في
`docs/BACKUP-AND-RESTORE.md §8`.

**لا يعمل:** `npm run backup` على قاعدة مُدارة. ١٩ جدولاً يستعمل
`FORCE ROW LEVEL SECURITY`، و`pg_dump` يرفض التصدير إلا لـsuperuser أو لدور
بـ`BYPASSRLS` — ولا يمنحك المزوّد المُدار أيّاً منهما. تبقى لقطاته هو.

**ثلاثة أشياء لا تكون مجانية بأي حال:**

| | لماذا |
|---|---|
| **التخزين** | الملف الأصلي يصل إلى **١ غيغابايت** لملفات Revit والمشاريع المضغوطة، و٣٠٠ ميغابايت لـCAD، و٢٠٠ لـPDF (`MAX_UPLOAD_BYTES`). أي طبقة تخزين مجانية تنفد بعد ملفات قليلة. **وهذا بالضبط أول بند يستحق الدفع.** |
| **النطاق** | `enginora.com` (قرارك على OPEN-8). روابط canonical وخريطة الموقع تُبنى من `APP_URL`، فتغييره لاحقاً يعني فهرسة من الصفر — ونطاق البريد يجب أن يطابقه وإلا صُنِّفت رسائل التأكيد مزعجة |
| **HTTPS** | ليس ترفاً: كعكة الجلسة `__Host-` و`Secure`، فبلا HTTPS **لا يستطيع أحد تسجيل الدخول**. شهادة Let's Encrypt مجانية، لكن يجب أن تكون موجودة من اليوم الأول |

**قبل أن تختار مزوّداً، اختبر التسجيل عنده أولاً.** المنصة تُدار من سوريا، وكثير
من المزوّدين يقيّدون التسجيل أو يوقفون الحسابات لاحقاً. اكتشاف ذلك **بعد**
الإطلاق يعني فقدان الحساب ومعه بيانات العملاء وسجل المبيعات. عشر دقائق من
الاختبار الآن أرخص من ذلك بكثير.

## ٢. أدوار قاعدة البيانات — ثلاثة، لا واحد

هذا ليس تفصيلاً تنظيمياً؛ **هو نموذج الحماية نفسه**:

| الدور | من يستعمله | ما يملكه |
|---|---|---|
| `migrator` | الترحيلات فقط | يملك المخطط ويغيّره |
| `app_user` | التطبيق | `NOBYPASSRLS` — **لا يستطيع تجاوز سياسات الصفوف بأي حال** |
| superuser | النسخ الاحتياطي وإثبات RLS | خارج التطبيق تماماً |

`DATABASE_URL` **يجب** أن يكون `app_user`. وضع دور أعلى فيه يلغي كل الطبقة
بصمت: لا رسالة خطأ، ولا اختبار فاشل — فقط منصة لم تعد سياساتها تعني شيئاً.

```bash
psql "$ADMIN_URL" -f docker/postgres/init/01-roles.sql
npm run db:migrate      # بـ DATABASE_MIGRATION_URL (دور migrator)
npm run db:prove-rls    # إثبات أن app_user مقيَّد فعلاً — لا تتخطَّ هذه
```

## ٣. متغيّرات البيئة

المرجع الكامل في `.env.example`. الحرجة:

```bash
NODE_ENV=production          # لا تضعه في .env.local أبداً (KI-1)
APP_URL=https://enginora.com # منه تُبنى كل روابط canonical والخريطة
DATABASE_URL=postgresql://app_user:...     # app_user، وليس أي دور آخر
DATABASE_MIGRATION_URL=postgresql://migrator:...
SESSION_SECRET=<٤٨ محرفاً عشوائياً>
CONFIG_ENCRYPTION_KEY=<٤٨ محرفاً عشوائياً>
STORAGE_ENDPOINT=https://<خدمة S3>         # ليس file:// — يُرفض في الإنتاج
MAIL_TRANSPORT_URL=smtps://user:pass@host:465   # ليس log:// — يُرفض في الإنتاج
MAIL_FROM="إنجينورا <no-reply@enginora.com>"
MALWARE_SCANNER=clamav                     # 'none' قرار يُسجَّل، لا افتراض
SEO_INDEXABLE=true                         # على الإنتاج وحده، عند الإطلاق
```

**الإعداد الخاطئ يوقف الإقلاع، لا يظهر لاحقاً.** أضيف في P8 فحصان متقاطعان:
تخزين على القرص في الإنتاج، وفهرسة مفعّلة مع `APP_URL` يشير إلى localhost.
كلاهما كان سيُنتج خادماً يعمل ثم يفشل متأخراً — الأول عند أول إيصال دفع
يُفتح، والثاني بخريطة موقع مليئة بروابط `localhost` تسجّلها محركات البحث.

وأُضيف ثالث مع التسجيل الذاتي: **`log://` في الإنتاج**. بهذه القيمة يُكتب البريد
في السجلّ بدل إرساله، فيُقلع الخادم سليماً، ويقبل التسجيلات، ولا تصل رسالة
التأكيد إلى أحد. لا أحد يبلّغ عن هذا كعطل — الزبون ببساطة لا يعود. لذلك يُرفض
عند الإقلاع، ويُرفض ثانيةً عند أول محاولة إرسال.

**البريد شرط للبيع، لا إضافة.** العميل يسجّل بنفسه ولا يستطيع الشراء قبل تأكيد
عنوانه (OPEN-23)، فخادم بريد لا يعمل يعني موقعاً لا يبيع. جرّب الإرسال فعلياً
قبل الإطلاق: أنشئ حساباً بعنوان تملكه، وتأكّد أن الرسالة وصلت إلى صندوق الوارد
لا إلى البريد غير المرغوب. اضبط SPF وDKIM على النطاق — بدونهما تُصنَّف رسائل
التأكيد رسائل مزعجة، وهو أكثر أسباب «لم تصلني الرسالة» شيوعاً.

**توليد المفاتيح:**
```bash
node -e "console.log(require('crypto').randomBytes(36).toString('base64'))"
```

## ٤. البناء والتشغيل

### أ. بحاويات — الطريق الموصى به لخادم واحد

```bash
cp .env.production.example .env.production      # ثم املأ كل قيمة
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build
docker compose -f docker-compose.prod.yml exec app npm run db:migrate
docker compose -f docker-compose.prod.yml exec app npm run bootstrap:owner
```

**قاعدة البيانات غير معرَّضة للإنترنت** (لا `ports:` لها)، والتطبيق مربوط
بـ`127.0.0.1:3000` — يصل إليه الوسيط العكسي وحده. ولا TLS في هذه الحزمة: ضع
Caddy أو nginx أمامها. **بلا HTTPS لن يستطيع أحد تسجيل الدخول أصلاً**، لأن
كعكة الجلسة `Secure` و`__Host-` — وهذا عمل الكعكة لا عطل يُلتَفّ عليه.

> **الصورة لم تُبنَ في بيئة التطوير هذه**: سياسة الشبكة تحجب شبكات توزيع
> طبقات الصور، فتعذّر `docker build`. المكتوب في `Dockerfile` يذكر بدقة ما
> تحقّقتُ منه وما لم أتحقّق منه. **ولا تستعمل `output: 'standalone'`** — يكسر
> توجيه اللغة (KI-2 في `docs/KNOWN-ISSUES.md`).

### ب. مباشرة على الخادم



```bash
npm ci
npm run db:migrate
npm run build          # حارس prebuild يرفض NODE_ENV غير production
npm start
```

ثم **قبل توجيه أي زيارة إلى الخادم**:

```bash
curl -fsS https://<النطاق>/api/health
node scripts/security-probe.mjs https://<النطاق>   # بحسابات اختبارية فقط
```

## ٥. الوسيط العكسي

| الترويسة | من يضعها |
|---|---|
| `Content-Security-Policy` مع nonce | التطبيق (`src/proxy.ts`) — **لا تُضِفها في الوسيط**، ستُلغي الـnonce وتُعطِّل كل نصوص الصفحة |
| `X-Forwarded-For` | الوسيط — يعتمد عليها تحديد المعدّل وسجل التنزيلات |
| `X-Forwarded-Proto: https` | الوسيط |
| ضغط `application/xml` | **الوسيط** — Next لا يضغط `sitemap.xml` وحجمها ٨١٩ KB |

Next يتحقق من `Origin` مقابل `Host` لكل server action. إن أنهى الوسيط اسم مضيف
مختلفاً، اضبط `serverActions.allowedOrigins` في `next.config.ts`، وإلا **رُفض
كل نموذج في الموقع** برسالة عامة.

## ٦. قائمة ما قبل الإطلاق

### يوقف الإطلاق

- [ ] `DATABASE_URL` هو `app_user`، و`npm run db:prove-rls` ينجح
- [ ] `npm run verify` و`npm run test:integration` خضراوان على الالتزام المنشور
- [ ] `node scripts/security-probe.mjs` — ٤٨ فحصاً، كلها PASS
- [ ] `npm run backup` ثم `npm run restore-drill` على **الإنتاج**، لا على نسخة تطوير
- [ ] HTTPS، وشهادة صالحة، وكعكة `__Host-em_session` تصل بـ`Secure`
- [ ] `SESSION_SECRET` و`CONFIG_ENCRYPTION_KEY` **ليسا** قيمتي `.env.example`
- [ ] `MALWARE_SCANNER` قرار مُتَّخذ ومُسجَّل
- [ ] حساب المالك أُنشئ بـ`npm run bootstrap:owner` بكلمة مرور قوية، و**TOTP مفعّل**
- [ ] النسخ الاحتياطي مجدول، ووجهته خارج هذا الخادم (OPEN-10)

### يجب أن يُقرَّر قبل الإطلاق

- [ ] **OPEN-8** — الاسم والنطاق والشعار. الأيقونة الحالية مؤقتة عمداً
- [ ] **OPEN-23** — هل يفتح تسجيل ذاتي للعملاء؟ لا توجد اليوم أي واجهة لإنشاء حساب، **والشراء يحتاج حساباً**
- [ ] **OPEN-9** — الضريبة والفوترة القانونية
- [ ] **OPEN-10** — مكان النسخ ومن يملك اعتمادها، وكم عملاً يُقبل فقدانه
- [ ] اعتماد `docs/SECURITY-REVIEW.md`

### بعد أن يعمل كل ما سبق

- [ ] `SEO_INDEXABLE=true` — **آخر خطوة**، وعلى النطاق الحقيقي وحده
- [ ] تحقّق أن `robots.txt` صار يعرض قواعد المنع لا `Disallow: /`
- [ ] قدّم `sitemap.xml` لأدوات المشرفين

## ٧. أدلة التشغيل

### «المستخدمون لا يستطيعون تسجيل الدخول»

1. `curl https://<النطاق>/api/health` — إن فشل فالمشكلة في قاعدة البيانات.
2. ابحث في السجلّ عن `Login failed unexpectedly`. وجودها يعني خطأً غير متوقع لا
   كلمة مرور خاطئة.
3. **إن كانوا يرون «محاولات كثيرة»** فهذا يعمل كما صُمّم: ٢٠ محاولة لكل IP و١٠
   لكل حساب في خمس دقائق، وقفل بعد ٨ محاولات خاطئة. الرسالة تذكر مدة الانتظار.
   لفكّ قفل حساب بعينه:
   ```sql
   UPDATE users SET locked_until = NULL, failed_login_count = 0 WHERE email = '...';
   DELETE FROM rate_limit_buckets WHERE key LIKE 'login:%';
   ```
   **انتبه:** خلف وسيط لا يمرّر `X-Forwarded-For` تُحسب كل الزيارات من IP واحد،
   فيُقفل الجميع معاً. إن رأيت قفلاً جماعياً فابدأ من هنا.

### «الصفحات فارغة أو لا تستجيب الأزرار»

الأغلب سياسة المحتوى. افتح أدوات المطوّر وابحث عن `Refused to execute`. السبب
الشائع ترويسة `Content-Security-Policy` يضيفها الوسيط فتحلّ محلّ ترويسة التطبيق
وتُسقط الـnonce. **احذفها من الوسيط.** وللتأكد:
```bash
node scripts/csp-check.mjs https://<النطاق>
```

### «إيصال الدفع يعطي خطأ ٥٠٠»

اقرأ السجلّ. إن ظهر `Filesystem storage is not permitted in production` فالإعداد
`STORAGE_ENDPOINT` ناقص. منذ P8 يُرفض هذا عند الإقلاع، فوجوده يعني أن الخادم
يعمل بإعداد قديم — أعد تشغيله.

### «الموقع بطيء»

```bash
node scripts/measure-pages.mjs https://<النطاق>
```
الأرقام المرجعية وحدودها في `docs/PERFORMANCE.md`. **أي قياس تُجريه بيدك على
قاعدة البيانات يجب أن يكون بدور `app_user`**؛ superuser يتجاوز RLS فيخفي معظم
التكلفة.

### «رقم في تقرير مالي يبدو خاطئاً»

**لا تُعدّل أي صف.** الدفاتر ملحقة لا تُعدَّل، والمحفّزات سترفض، والمحاولة
تكسر سلسلة التجزئة.

1. `/admin/finance` يعرض فحص السلامة: مجموع كل عملة يجب أن يكون صفراً، ومشاكل
   السلسلة صفراً.
2. إن كان الرقم خاطئاً فعلاً، فالتصحيح **قيد جديد** عبر `/admin/adjustments`:
   يعرض الرصيد قبل وبعد، ويطلب تأكيداً صريحاً، ويكتب سجل تدقيق ويُشعر المهندس.
3. الكشوف الصادرة سابقاً **لا تتغيّر**. التصحيح يظهر في كشف الشهر الذي كُتب فيه.

### «فقدنا قاعدة البيانات»

`docs/BACKUP-AND-RESTORE.md` §٥. باختصار: تحقّق من البصمات، استعد الأدوار أولاً
ثم القاعدة، ثم **شغّل `restore-drill` و`db:prove-rls` قبل تشغيل التطبيق**.
استعادة فقدت سياسة RLS تبدو سليمة تماماً من الخارج وتكون قد فتحت الدفاتر
للجميع.
