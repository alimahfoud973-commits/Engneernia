## ٠. رابط المعاينة — اقرأ هذا أولاً

**لا يوجد رابط تستطيع فتحه من متصفحك الآن.**

أنا أعمل داخل حاوية سحابية معزولة. شغّلتُ المنصة فعلاً وهي تعمل، لكنها تستمع على
`localhost` **الخاص بتلك الحاوية**، ولا يوجد أي طريق من جهازك إليه. إعطاؤك
`http://localhost:3000` سيفتح جهازك أنت، لا المنصة.

ولم أفتح نفقاً عاماً (مثل Cloudflare Tunnel) عمداً: ذلك **نشرٌ على الإنترنت**،
وأنت طلبت صراحةً ألّا نعتبرها منشورة، وسيعرّض بناء تطوير ببيانات اختبار
للعلن بلا داعٍ.

### كيف تفتحها على جهازك — خمس خطوات

```bash
git clone https://github.com/alimahfoud973-commits/Engneernia
cd Engneernia
git checkout claude/gracious-wozniak-y80791
npm ci

cp .env.example .env.local
# ثم بدّل قيمتين فقط في .env.local:
#   SESSION_SECRET=<32 بايت عشوائية base64>
#   CONFIG_ENCRYPTION_KEY=<32 بايت عشوائية base64>
#   ولّدهما بـ:  openssl rand -base64 32
# وصحّح مسار التخزين ليطابق مكان المشروع عندك:
#   STORAGE_ENDPOINT=file:///<المسار الكامل للمشروع>/.data/storage

docker compose up -d          # PostgreSQL (وMinIO إن أردت)
npm run db:migrate
npm run seed:catalog && npm run seed:demo
npm run bootstrap:owner       # تفاعلي: بريد المالك وكلمة مروره
npm run dev
```

ثم افتح **`http://localhost:3000`** — هذه المرة على جهازك، فتعمل.

> **بلا Docker؟** `bash scripts/dev-db.sh` يشغّل PostgreSQL محلياً بلا حاويات.
> **وبلا MinIO؟** لا حاجة إليه: `STORAGE_ENDPOINT` بصيغة `file://` يفعّل محوّل
> نظام الملفات المحلي، **وقد اختبرتُه فعلاً** (§٣.٦) — رفع ملف، توليد معاينة،
> وتنزيل نسخة مختومة، كلها بلا MinIO ولا S3.

## ١. ما أُصلح

### عيب تسجيل الدخول في التطوير — **مُصلَح**

**العَرَض:** تسجيل الدخول في `npm run dev` لا يثبت. الصفحة التالية للدخول تظهر
صحيحة، ثم أي نقرة بعدها تعود ضيفاً. كل `/account` و`/admin` غير قابلة للوصول.

**السبب:** اسم الكعكة `__Host-em_session`. وبادئة `__Host-` وعدٌ **يفرضه
المتصفح**: لا يقبل الكعكة إلا مع `Secure` و`Path=/` وبلا `Domain`. وكان الاسم
ثابتاً يحمل البادئة بينما `secure: isProduction` — أي `false` في التطوير. فكانت
كل عملية دخول تُرسل كعكة **يرميها كل متصفح بصمت**: لا خطأ، ولا تحذير، ولا طلب
فاشل.

ولماذا بدت الصفحة التالية سليمة؟ لأن Next يُصيّر وجهة إعادة التوجيه **داخل
الطلب نفسه**، حيث الكعكة ما زالت في السلة. النقرة التالية كانت ضيفاً.

**الإصلاح:** الاسم وعلامة `Secure` صارا قراراً واحداً مشتقاً من نفس القيمة
المنطقية، فلا يمكن أن يفترقا. التطوير يتخلّى عن **البادئة** لا عن الضمان: اسم
عادي فوق HTTP عادي لا يدّعي ما لا يستطيع الوفاء به، **ويبقى يعمل على عنوان
شبكة محلية** (لاختبار من الهاتف) حيث كان `Secure` سيُرفض من جديد.

**الحارس:** `src/auth/session-cookie.test.ts` يفحص **الزوج** لا أحد نصفيه، في
البيئتين. أعدتُ العيب الأصلي فسقط اختباران، ثم أعدته فمرّا.

## ٤. `settlement_lines.gross_minor` — القرار المطلوب منك

**لم أغيّر شيئاً.** هذا شرح لما يحتاج قراراً.

### ما يسجّله النظام اليوم

```sql
oi.unit_price_minor  AS gross      -- سعر المنتج الكامل
oic.amount_minor     AS engineer   -- أجر هذا المهندس
```

`unit_price_minor` هو **سعر القائمة الكامل**: شامل الضريبة، وقبل الخصم، وعن
**المنتج كله** لا عن حصة هذا المهندس.

### لماذا صار ملتبساً بعد OPEN-15

أجر المهندس صار يُحسب من **حصته** — أي `(السعر − الخصم − الضريبة) × نسبة
مساهمته` — ثم `× نسبة عمولته هو`.

فعلى منتج مشترك، كشفُه يضع رقمين لا تربطهما علاقة قابلة للشرح:

```
سعر المنتج    ١٠٠٫٠٠     ← المنتج كله، شامل الضريبة، قبل الخصم
حصتي          ٢٨٫٠٠      ← ٤٠٪ مساهمة × ٧٠٪ عمولة، بعد الخصم والضريبة
```

والمهندس لا يستطيع التحقّق من أجره من كشفه. والأسوأ أن
`settlements.period_gross_sales_minor` — المطبوع على كشف PDF كـ**«إجمالي
قيمتها»** — هو مجموع هذه الأرقام، فيُضخّم «مبيعاتي» على المنتجات المشتركة:
يَعدّ سعر المنتج كاملاً بما فيه حصص الزملاء.

### الخيارات — اختر واحداً

| # | ما يُسجَّل | «إجمالي قيمتها» يصير | الميزة | العيب |
|---|---|---|---|---|
| **أ** | كما هو: سعر القائمة الكامل | قيمة المنتجات التي شارك فيها | لا تغيير، ولا ترحيل | يضخّم مبيعات المشترك، ولا يُفسَّر بجانب الحصة |
| **ب** | المدفوع فعلاً (بعد الخصم) عن المنتج كله | ما دفعه العملاء فعلاً | صادق عن البيع | يبقى مضخَّماً على المشترك |
| **ج** | **حصة هذا المهندس** (بعد الخصم والضريبة) | ما يخصّه هو فقط | **الأجر يصير قابلاً للتحقّق**: `حصتي × نسبتي` | يختلف عن السعر المعروض، فيحتاج شرحاً على الكشف |
| **د** | حصته + نصيبها من الضريبة | نظير «إجمالي» يخصّه | يقابل السعر شكلاً | أعقد، وبلا فائدة عملية والضريبة صفر |

**رأيي: (ج).** الكشف مستند للمهندس عن **ماله هو**، لا عن قيمة المنتج. وهو
الوحيد الذي يجعل السطر يُفسِّر نفسه. ويحتاج: تغيير سطر واحد في
`readStatementDetail`، وترحيلاً يعيد تسمية العمود، وسطراً على PDF يقول
«قيمة حصتك».

**وما لا يتغيّر في كل الخيارات:** أي مبلغ مدفوع، أو قيد دفتر، أو كشف صادر —
الأرقام المالية كلها مجمَّدة، والتغيير **عرضٌ فقط**.

## ٦. نسبة الاكتمال

| المحور | الاكتمال | ملاحظة |
|---|---|---|
| البنية والأمن وRLS | **٩٨٪** | ٣٦٩ اختبار تكامل، والصلاحيات مُثبتة لا مُدّعاة |

| **أدوات المالك** | **٥٥٪** | المال والتسوية والعمولات ✅ — **المنتجات والأسعار والمهندسون والملفات ❌** |
| الجاهزية للإطلاق | **٤٠٪** | ينقص: بريد، وبوابة دفع، واستضافة، ومحتوى حقيقي |

### **الاكتمال الكلي ≈ ٨٢٪**

**اقرأها هكذا:** المنصة **مبنية** إلى حدٍّ بعيد وآمنة ومُختبَرة. لكن المالك
لا يستطيع بعد **تشغيلها بنفسه من المتصفح**: لا يضيف منتجاً، ولا يسعّره، ولا
يرفع ملفاته، ولا يضيف مهندساً. هذه ٤٥٪ الناقصة من أدوات المالك، وهي أقرب
عقبة بينك وبين اختبار حقيقي من طرف إلى طرف.
