## ٤. قرارات يجب عدم مخالفتها

- **الدفع (Stage 7، DECISIONS §٢٣)**: كل محاولة دفع صف مستقل، ودفعة **مفتوحة** واحدة على الأكثر لكل طلب
  (`INITIATED`/`AWAITING_PROOF`/`PROOF_SUBMITTED`)؛ الدفعة النهائية (`APPROVED`/`REJECTED`/`CANCELLED`)
  لا تتغيّر. تغيير الطريقة قبل الإيصال يغلق القديمة `CANCELLED`، وبعده مرفوض. كل مسار يغيّر طلباً أو دفعته
  يقفل صف الطلب أولاً ويكتب من الحالة التي رآها. المشتري لا يكتب صف دفعة إلا عبر دالتي 0057 و0066.
- **السعر المتفق عليه يُثبَّت عند إنشاء الطلب**: الاعتماد والفاتورة والدفتر والعمولة على سعر البند، لا
  على سعر المنتج الحالي؛ اتفاق العمولة والضريبة يُقرآن وقت الاعتماد. الطلب المجاني الذي أُنشئ والمنتج
  مجاني يكتمل مجاناً؛ الطلب الجديد يُسعَّر دائماً من السعر الحالي.
- **الإلغاء**: المشتري من `DRAFT`/`AWAITING_PAYMENT`/`PAYMENT_ISSUE`؛ المالك منها ومن
  `PROOF_SUBMITTED`/`PENDING_VERIFICATION` بسبب إلزامي وإشعار للمشتري؛ لا أحد من `PAID`/`COMPLETED`/
  `CANCELLED`/`REFUNDED`. **لا استرداد ولا قيد عكسي** — أي تسوية خارج المنصة.
- **الطرق اليدوية تتطلب الإيصال دائماً** (يُفرض في خدمة طرق الدفع وفي نموذجها).
- **المصادقة (Stage 6، DECISIONS §٢٢)**: المشترك يسجّل بالاسم والهاتف والبريد فقط، ويصير
  `ACTIVE CUSTOMER` مسجَّل الدخول فوراً؛ لا كلمة مرور، ولا موافقة مالك، ولا `PENDING`، ولا تأكيد بريد.
  يدخل المشترك **والمهندس** بالهاتف والبريد معاً. المالك وحده باسم مستخدم وكلمة مرور (`/login/owner`)،
  **بلا عامل ثانٍ**. الهاتف E.164 فريد، ولا يُفترض رمز دولة. **الخطر المقبول**: الهاتف والبريد ليسا
  سرّاً — قرار المالك الصريح، لا عيب.
- **المنتج المجاني** يكتمل فوراً بلا دفعة (`app_complete_free_order`).
- **لا بيع بلا اتفاق عمولة سارٍ** للمنتج المدفوع، ولا نسبة عمولة افتراضية في الكود.
- **بيانات طريقة الدفع تُنسخ على الدفعة** عند إنشائها؛ تعديل الطريقة لا يمس طلباً قائماً.
- **رقم واتساب يُقرأ من الإعدادات لحظة بناء الرابط**، ولا يُنسخ على الطلب.
- **المعاينة تُقدَّم من أصل الموقع نفسه دائماً** (تُقرأ من التخزين وتُبثّ، لا تحويل

## ٨. معلومات تقنية للمتابعة

**التشغيل المحلي**
```bash
docker compose up -d            # PostgreSQL + RustFS + تهيئة الـ buckets
docker compose up -d postgres   # Postgres وحده (التخزين الافتراضي file://)
npm run db:migrate              # بعد كل pull فيه ترحيل جديد
npm run verify                  # قبل أي commit
npm run test:integration        # يحتاج قاعدة حقيقية
```
- لاستعمال RustFS بدل القرص: `STORAGE_ENDPOINT=http://localhost:9000` في `.env.local`.
  المفاتيح `minioadmin` وأسماء الـ buckets كما في `.env.example`.

**CI** (`.github/workflows/ci.yml`): خدمتا `postgres:16-alpine` و`rustfs/rustfs:1.0.0`،
ثم npm ci ← typecheck ← lint ← وحدة ← إثبات RLS ← ترحيلات ← seeds
(`seed:catalog` `seed:demo` `seed:scale`) ← إنشاء الـ buckets ← تكامل ← بناء ← `npm audit --omit=dev --audit-level=high`
← `node scripts/audit-gate.mjs` (TD-50).

**قاعدة مؤقتة للتجارب** (كما يفعل CI): أنشئ القاعدة، امنح `migrator` كل الصلاحيات
و`app_user` الاتصال، واجعل `migrator` مالك `public` مع
`ALTER DEFAULT PRIVILEGES FOR ROLE migrator ... TO app_user` (انظر
`docker/postgres/init/01-roles.sql`)، ثم `db:migrate` والـ seeds، واحذفها بعد الانتهاء.
`seed:demo-media` يحتاج صف مالك موجوداً.

**مزالق مُثبتة**
- `next dev` يُلحق كتلة قواعد بـ `CLAUDE.md` حين يكتشف أنه يعمل داخل وكيل ذكي؛
  شغّله بـ `env -i PATH="$PATH" HOME="$HOME" npx next dev` لتفاديه.
- Drizzle يحلّل عمود `jsonb` مرتين: نص مثل `"2026"` يعود رقماً. اقرأ الإعدادات
  النصية بـ `${settings.value}::text` ثم `JSON.parse` (كما في `settings.ts`
  و`tax-policy.ts`).
- header في `next.config.ts` يتغلّب على header يضعه المسار لنفس المفتاح.
- `npm` يرفض بـ `EBADPLATFORM` أي تبعية مباشرة غير اختيارية لمنصة أخرى.

**بيئة Claude Code السحابية** (خاص بها، مُتحقَّق منه):
- Postgres المحلي: `bash scripts/dev-db.sh` (قد يتوقف عند إعادة تشغيل الحاوية).
- Docker: يلزم تشغيل `dockerd` يدوياً؛ quay.io محجوب بسياسة الشبكة؛ Docker Hub
  قد يرد 429.
- `gh` غير متاح؛ حالة CI تُقرأ من واجهة GitHub العامة أو أدوات MCP.
