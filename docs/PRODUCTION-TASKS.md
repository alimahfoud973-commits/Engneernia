# مهام النشر المؤجَّلة

> **المرحلة الحالية: تطوير محلي فقط، بقرار المالك.** لا يُشترى ولا يُضبط أي
> خدمة خارجية الآن. كل ما في هذه الوثيقة **مؤجَّل إلى مرحلة النشر**، ولا شيء
> منه يوقف التطوير.

كل بند هنا يُوصَل لاحقاً **بمتغيّر بيئة أو صفٍّ في `settings`**، لا بتعديل كود.
هذه ليست نية حسنة: `src/lib/config/portability.test.ts` يفشل البناء إذا قرأ أي
ملف تحت `src/` متغيّراً غير مُعلَن في `src/lib/config/env.ts` وموثَّق في
`.env.example` — فالخانة التي تُملأ يوم النشر معروفة اليوم.

## ١. الخادم (VPS)

| | |
|---|---|
| **جاهز** | `docker-compose.prod.yml` و`Dockerfile` و`deploy/Caddyfile` |
| **ناقص** | خادم يُشغَّل عليه |
| **يُوصَل بـ** | لا شيء في الكود. نسخ `.env.production.example` وملؤه |
| **لم يُتحقَّق منه** | `docker build` — سياسة الشبكة هنا تحجب طبقات الصور. و`deploy/Caddyfile` لم يُشغَّل: لا Caddy في هذه البيئة. شغّل `caddy validate` على الخادم أولاً |

## ٢. تخزين الكائنات (S3)

| | |
|---|---|
| **جاهز** | `S3Storage` — و**صار مُختبَراً فعلياً** مقابل خادم HTTP يتكلم S3 داخل العملية (`src/media/storage/s3.test.ts`): رفع وتنزيل ومطابقة بايتات، وعنونة بالمسار، ورابط موقّع يُنزِّل فعلاً باسم عربي |
| **محلياً الآن** | `file://` عبر `LocalFilesystemStorage`، ونفس الواجهة تماماً |
| **يُوصَل بـ** | `STORAGE_ENDPOINT` وأربعة متغيّرات معه |
| **ما يبقى مجهولاً** | سلوك مزوّد بعينه: حدود الحجم، وسرعة الرفع، وشكل أخطائه. الكود نفسه لم يعد مجهولاً |

## ٣. البريد الصادر

| | |
|---|---|
| **جاهز** | `SmtpEmail` — **مُجرَّب من طرف إلى طرف**: تسجيل ← إرسال عبر SMTP حقيقي ← رسالة عربية مُرمَّزة صحيحاً ← تأكيد ← حساب `ACTIVE` |
| **محلياً الآن** | `log://` يكتب الرسالة في السجلّ. **مرفوض في الإنتاج** عند الإقلاع وعند أول إرسال |
| **يُوصَل بـ** | `MAIL_TRANSPORT_URL` و`MAIL_FROM` |
| **ما يبقى مجهولاً** | أن يقبلك المزوّد، وأن تمرّ رسالتك من مرشّح المزعج — وذلك SPF وDKIM على نطاقك، لا شيء في المستودع |

## ٤. النطاق `enginora.com` وDNS وHTTPS

| | |
|---|---|
| **جاهز** | لا وجود لأي نطاق مكتوب في كود التطبيق. كل رابط canonical وكل مدخل في خريطة الموقع يُبنى من `APP_URL` |
| **يُوصَل بـ** | `APP_URL` وحده |
| **انتبه** | الشهادة تجلبها Caddy تلقائياً، لكن **بلا HTTPS لا يستطيع أحد تسجيل الدخول**: كعكة الجلسة `Secure` و`__Host-` |

## ٥. فحص البرمجيات الخبيثة (ClamAV)

| | |
|---|---|
| **جاهز** | `ClamAvScanner` خلف نفس المنفذ، و`CLAMAV_HOST` و`CLAMAV_PORT` صارا مُعلَنين ومُتحقَّقاً منهما وموثَّقين (كانا يعيشان في الكود وحده) |
| **محلياً الآن** | `MALWARE_SCANNER=none`: الملف يُوسَم `SKIPPED` |
| **الأثر** | `isServable` **ترفض تقديم `SKIPPED` في الإنتاج**. فالنتيجة قيدٌ يمنع البيع، لا ثغرة تسمح به |

## ٦. النسخ الاحتياطي خارج الخادم (OPEN-10)

| | |
|---|---|
| **جاهز** | التشفير والشحن والتمرين: `npm run backup`، `backup:ship`، `restore-drill` |
| **ناقص** | دلو ثالث **بحساب منفصل تماماً** ومفتاح تشفير يُحفظ خارج الخادم |
| **يُوصَل بـ** | متغيّرات `BACKUP_*` — **ولا تدخل بيئة التطبيق أبداً**، مهمّة cron وحدها تراها. يحرس ذلك `backup-isolation.test.ts` |

## ٧. الفهرسة في محركات البحث

`SEO_INDEXABLE=true` **آخر خطوة على الإطلاق**، وعلى النطاق الحقيقي وحده.
الافتراض `false`، وهو الافتراض الآمن: نسخة تجريبية نسيت الإعداد تبقى خارج
الفهرس، أما نسخة إنتاج نسيته فتبقى غير مرئية حتى ينتبه أحد — والعكس يضع
كتالوجاً نصف جاهز، وأسماء المهندسين عليه، في Google بشكل شبه دائم.

## ٨. GitHub

الفرع الافتراضي في المستودع ما زال `_probe_write_access`. تغييره نقرة واحدة في
إعدادات المستودع، ولا يمكن فعله من هنا.

## ما لا ينتظر شيئاً

التطوير والاختبار يمضيان كاملين بلا أي خدمة مدفوعة: قاعدة PostgreSQL محلية،
وتخزين `file://`، وبريد `log://`، و٦١٧ اختبار وحدة و٢٧٨ اختبار تكامل و٦٠ فحص
مسبار أمني — كلها تعمل هنا. القيد الوحيد الذي تفرضه هذه المرحلة هو أن ما في
§١ أعلاه لم يُشغَّل على خادم حقيقي بعد.
